# Sacred-v2 Torque and Nova Eye Audit

Audited: 2026-07-26

## Scope

Read-only source root:

`/Users/chetanpatil/Desktop/test/livnium-sacred-v2`

The audit inventoried artifacts, compared hashes with earlier sacred branches,
replayed all three unique torque checkpoints on complete SNLI dev and test
splits, isolated the label-routing path, ran post-hoc mechanism ablations, and
inspected the unfinished `nova_eye` branch. No source project, model, dataset, or

## Short conclusion

Sacred-v2 contains a real continuation of the March sacred NLI work, but it does
not contain the remembered 96% model.

- The best surviving checkpoint is
  `system/snli/nova_v3/model/torque-256-memory/best_model.pt`. It freshly scores
  **7,531/9,842 = 76.52%** on SNLI dev and
  **7,507/9,824 = 76.42%** on SNLI test using deterministic, static,
  label-blind inference.
- The three saved torque-family models remain around 75.6–76.5%; none approaches
  96%.
- The stock evaluators do expose gold labels to dynamic basin routing. That is a
  genuine leak path. However, static, stored-label, and globally shuffled-label
  routing change at most six predictions for the surviving checkpoints, so the
  leak does not explain their approximately 76% scores.
- Per the recovery decision made on 2026-07-26, the historical
  **95.76% dev / 96.07% test** claim is provisionally classified as
  **leaked/unusable**. It may be re-opened only if its missing checkpoint,
  prediction file, or independently reproducible protocol is found.
- The named fixed axial/anchor/torque forces are not load-bearing in the saved
  models. Zeroing them post hoc leaves predictions essentially unchanged.
  Bypassing or zeroing the learned repeated residual update drops test accuracy
  to roughly 59–66%, showing that the learned update is the active component.
- “Failure memory” records mistakes but never changes the loss, gradients,
  routing, or inference. The memory checkpoint's improvement cannot be credited
  to that mechanism.
- The `nova_eye` branch contains valuable raw-character, retina/glyph, emergent
  basin, watcher, WebSocket, and Flutter ideas, but no completed Eye checkpoint
  or evaluation result. Its actual trainer uses ordinal character values rather
  than the retina/glyph pipeline and has a first-epoch statistics-key crash.

Preservation role:
**canonical late sacred torque continuation plus incomplete Nova Eye design
archive**.

## Fresh deterministic replay

The temporary evaluator:

- loaded the exact raw SNLI splits;
- restored each saved model state;
- disabled encoder noise;
- compared static, saved-label dynamic, and globally shuffled-label dynamic
  routing; and
- used the actual class mapping entailment, contradiction, neutral.

### Label-blind static results

| Checkpoint | SNLI dev | SNLI test |
|---|---:|---:|
| torque-v1 | 76.07% | 76.00% |
| torque-replace-256 | 75.57% | 75.82% |
| torque-256-memory | **76.52%** | **76.42%** |

The `torque-256-memory` static test confusion matrix, with rows and columns in
entailment, contradiction, neutral order, is:

```text
[[2817, 160, 391],
 [ 244,2536, 457],
 [ 567, 498,2154]]
```

The saved scripts label their printed confusion headers entailment, neutral,
contradiction even though the dataset and logits use entailment, contradiction,
neutral. This is a reporting bug, not a model-score change.

### Label-leak sensitivity

| Checkpoint | Static dev/test | Stored-label dev/test | Shuffled-label dev/test |
|---|---:|---:|---:|
| torque-v1 | 76.0719 / 75.9976 | 76.0719 / 76.0077 | 76.0821 / 75.9874 |
| torque-replace | 75.5741 / 75.8245 | 75.5842 / 75.8143 | 75.5944 / 75.8143 |
| torque-memory | 76.5190 / 76.4149 | 76.4987 / 76.4353 | 76.4885 / 76.4454 |

Stored-label routing differs from static routing on only 0–3 dev predictions and
1–6 test predictions, depending on the checkpoint. Stored-label and shuffled
routing differ on at most one prediction per evaluated split.

Therefore:

1. the evaluator interface is contaminated because it accepts gold labels;
2. the approximately 76% surviving results are reproducible label-blind; and
3. the missing 96% result remains untrustworthy but cannot honestly be assigned
   as the source of the surviving models' scores.

## What actually carries the saved prediction

These are post-hoc diagnostics on co-adapted saved checkpoints, not matched
independently trained ablations.

### Fixed-force ablation

Forcing torque strength to zero leaves accuracy and almost every prediction
unchanged. Zeroing all fixed axial/anchor strengths plus torque produces the
same conclusion.

The names “torque,” “physics,” and fixed anchor forces therefore do not describe
the load-bearing computation in these saved states.

### Learned-update ablation

| Diagnostic | torque-v1 test | replacement test | memory test |
|---|---:|---:|---:|
| Full static model | 76.00% | 75.82% | 76.42% |
| Bypass all collapse layers | 65.80% | 60.11% | 61.44% |
| Zero learned update, retain fixed forces | 64.97% | 59.30% | 60.58% |

The repeated learned residual update is load-bearing in the saved prediction.
This supports preserving the iterative residual architecture while retiring any
causal statement that attributes the result to the named fixed physics forces.

The encoder tables also moved substantially from the pretrained collapse4
embedding table: mean matching-row cosine is about 0.912 for torque-v1, 0.906 for
replacement, and 0.887 for memory. The result belongs to supervised
fine-tuning of the entire pipeline.

## Replacement and failure-memory mechanisms

### Basin replacement

The replacement branch expands the basin field and adds replacement logic. Its
saved checkpoint is below both torque-v1 and torque-memory. Because seeds,
selected epochs, data order, and matched controls are absent, this is historical
negative evidence rather than a clean causal ablation.

### Failure memory

The saved memory state reports:

- 589,046 total failures recorded;
- 1,610,960 total resolved observations; and
- roughly 62–63 active records in each directed class-confusion bucket.

The code defines difficulty boosts and exposes a `failure_boost` command-line
argument. But the training loop explicitly uses the standard loss and never
applies the difficulty boost. The memory is a silent observer: it records model
behavior but cannot affect learning or inference.

Preserve the error-memory ledger as an observability idea. Retire the claim that
it caused the memory checkpoint's higher score.

## Nova Eye branch

The `system/snli/nova_eye` tree is not a completed model. Its `model/eye-v1`
directory is empty, and `run_100k.log` stops while encoding dev data before any
epoch result or checkpoint.

### Ideas worth preserving

- direct raw-character input rather than word-token lookup;
- a fixed center-surround retina stage plus learned local CNN;
- glyph patch and top/bottom spatial features;
- an emergent label-free basin field;
- a watcher head that reads a detached collapse trajectory and raw signal;
- a diagnostic WebSocket server and Flutter terminal UI.

### Current implementation boundaries

- The actual trainer uses `PixelEncoder`, which converts the first 256
  characters to clipped ordinal values and applies a learned relation
  projection. It does not use `RetinaCNN`, `GlyphTokenizer`, or
  `DisplayRenderer`.
- Characters after position 256 are ignored; non-ASCII values such as `é` clip
  to 1.0.
- The display renderer keeps only six low ASCII bits, so distinct characters
  such as `a` and `!` render identically.
- The signal test evaluates without the emergent basin field even though the
  trainer uses it, producing a train/evaluation mismatch.
- After its first training epoch, the trainer asks for `mean_count` and
  `max_count`, while `EmergentBasinField.stats()` returns `mean_strength` and
  `max_strength`. The resulting `KeyError` prevents dev evaluation and
  checkpoint saving. This likely explains the empty `eye-v1` directory.
- The watcher is a legitimate separate-head experiment, but no saved result
  establishes that it helps.
- As in the torque branch, Eye failure memory only observes.

### Conservation check

The emergent basin code claims strict energy conservation, but focused checks
show:

- one newly born basin has total energy 1.0;
- strengthening it raises total energy to 1.1 when no other basin can donate;
- decay lowers total energy to 0.84 without redistributing the removed amount.

The implementation also clamps strengths, which can further alter totals.
Preserve “label-free emergent basin lifecycle” as an idea, but retire “strict
conservation” for the current code.

No executable assertion-based tests are present in either `nova_eye` or
`nova_v3`; their `test_*.py` files are diagnostic scripts. Combined pytest
collection also collides on duplicate module basenames.

## Preservation and continuation decision

- Preserve the entire sacred-v2 root.
- Treat `torque-256-memory` as the best freshly replayed surviving sacred
  checkpoint so far, at 76.52% dev and 76.42% test label-blind.

  leaked/unusable and never cite it as a valid benchmark.
- Preserve the learned iterative residual mechanism; do not credit the fixed
  torque/physics terms without matched retraining.

  observer/ledger idea.
